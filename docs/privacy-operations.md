# Foldbox — procédure de conservation et demandes

Document interne. Ne pas publier de données personnelles dans Git ou dans une issue publique.

## Chaque mois

1. Supprimer les écritures `showcase_submission_upload_usage` âgées de plus de 30 jours.
2. Examiner les soumissions `pending` ; aucune ne doit dépasser 12 mois.
3. Supprimer sous 30 jours les fichiers privés d’une soumission rejetée.
4. Vérifier les signalements reçus à l’adresse de contact.

## Demande d’une personne

1. Demander la référence de soumission ou, à défaut, le jeu, le pseudo et une preuve suffisante permettant de retrouver la donnée sans collecter d’information excessive.
2. Identifier la soumission, ses fichiers Storage, ses J’aime et son compte technique Supabase.
3. Répondre dans un délai d’un mois, sauf prolongation légalement justifiée et annoncée.
4. Pour un retrait : supprimer d’abord la version publique GitHub, puis les fichiers privés, la ligne de soumission et, si demandé, le compte technique et ses J’aime.
5. Conserver uniquement une trace minimale de la demande lorsque cela est nécessaire pour démontrer son traitement.

## Publication

Avant publication, vérifier le consentement, les droits sur les images, l’absence de données personnelles inutiles et la conformité aux règles de la communauté.
